# Patto 仕様書

オフラインでも使えるカンバン式TODOアプリ。Android・iOS・Web を同じコードで動かす。

## 1. 設計原則

1. **オフライン優先**: 操作はまず端末内のSQLiteに保存する。通信を待たずに動く。
2. **ハードコード禁止**: 色・文言・数値・アプリ名は専用ファイルに切り出す（12章）。
3. **レスポンシブ**: 画面幅とカンバン数に応じて表示列数を切り替える（スマホ縦=1列、スマホ横=最大3列、PC=1〜3列）。
4. **統一された操作体系**: プロジェクト・カンバン・タスクは作成/編集/削除/複製/復元が同じ流れ。
5. **秘密情報をアプリに入れない**: アプリに入るのは公開前提の Publishable Key のみ。データは RLS で保護する。

### レイヤー構成

- `src/config/` `src/theme/` `src/i18n/` 設定値・色・文言

### メニュー（左のサイドバー）

- 最上段: **アプリ名と、その右側の検索アイコン**。検索アイコンを押すと、全プロジェクトを対象にした検索ダイアログを開く。スマホでは画面上部のバーのメニューアイコンが横移動して見える位置にあり、そのアイコンでメニューを閉じる。
- 全プロジェクト検索: タスクのタイトル・説明を対象にする。結果は1件ごとに「プロジェクト名 › カンバン名」を上に薄く、続けてタスクのタイトルと説明を表示する。サイドメニュー内に検索欄や検索行は置かない。
- プロジェクト一覧（「プロジェクト」という見出しは出さない）: ピン留めを上に、左右に少し余白のある細い**横線**で区切って通常のプロジェクト（ピンのアイコン（Material Symbols の keep / keep_off）で表す。星は使わない）。各行に色の丸・タイトル（長いときは「…」）・タスク数（括弧なしの数字）（DONEモードを含み、アーカイブ・ごみ箱は含めない）・横3点メニュー。その**直下**に「プロジェクトを追加」（「タスクを追加」と同じ控えめな色）。アーカイブ済みは折りたたみ。
- 下部（左右いっぱいの横線の下。「設定」と同期表示は同じ大きさ）: 「設定」、ユーザー・同期状態（**タップすると今すぐ同期**）。
- 幅: PCは画面の約1/4（220〜400）、スマホは画面の約8割（右に一番左のカンバンが少し見える）。PCは左に常設（開閉可）、スマホは上記の、カンバンの左に並ぶ1ページ。
- スマホ: メニューは**いちばん左のカンバンのさらに左に並ぶ1ページ**で、画面の上端から下端までの全高。メニューの最上段にはアプリ名だけを表示する。画面上部のバーは右へずれて見え、メニューアイコンも同時に右へ移動する。メニューをカンバンの上に重ねるのではなく、画面全体（ヘッダーとカンバン）が右へずれてメニューが現れる。
- いちばん左のカンバンで左から右へスライドすると、カンバンを移動するときと**同じ操作・同じ吸着**でメニューが出る。**ヘッダーもカンバンと一緒に右へずれる**。メニューを開いた状態では、右側に一番左のカンバンが少し見える。ページ表示のドットや「1 / 3」は、メニューが見えている間は出さない。
- メニューを閉じるのは、左へスライド、メニュー側のアイコン、画面上部のバーのメニューアイコン（ずれて見えている場合）。プロジェクトを選んでもメニューは閉じない。
- メニューの開閉は**スクロール位置だけ**で決まり、別の場所に開閉の状態を持たない（互いに更新し合ってループしないための設計）。
- メニューが見えている間も、画面上部のバー（ずれて右に見えている）のメニューアイコンを表示する。メニューの開閉アニメーションが始まった時点で、ヘッダー側とメニュー側のアイコンを即時に同じ状態へ切り替える。操作がキャンセルされて元の位置へ戻った場合は、両方のアイコンも直ちに元の状態へ戻す。
- **プロジェクトの切り替え**: すでにプロジェクトの画面にいるときは、新しい画面を重ねず、同じ画面の中身だけを待ち時間なしで入れ替える。スマホでは、プロジェクトを選んでもメニューを閉じず、選んだプロジェクトのカンバンをメニューの背後で切り替える。ユーザーがメニューを閉じたときに、選んだプロジェクトの画面が表示される。データは端末内にあるので、読み込みを待つ必要はない。
- スマホで「設定」を押すと、設定画面の表示を切り替えてからメニューを閉じる。設定トップから下層画面へ移動するときは、その画面の遷移に合わせてメニューを閉じる。
- プロジェクトが選ばれていない画面（ホーム）では、スマホはメニュー（プロジェクト一覧）を画面いっぱいに表示する。
- 選択中のプロジェクトは、ホバーと区別できるよう**文字色と背景を反転**する（ライト=黒背景・白文字、ダーク=白背景・黒文字）。選択中の行の横3点ボタンは、ホバー時の背景も反転した色に合わせた半透明色にする。
- メニューの項目名は、プロジェクトは「プロジェクトの編集」、タスクは「タスクの編集」、カンバンは「カンバンの編集」。

### ボード画面の構成

- 設定などの画面のヘッダーは、戻るボタンを左に、タイトルを中央に置く。
- ヘッダー: 左にメニューアイコン、**中央にプロジェクト名（その横に同期状態アイコン）**、右に横3点メニュー。
- 右の横3点メニュー: カンバンを追加 / カンバン内を検索 / DONEタスクをアーカイブする / アーカイブを見る / アーカイブのクリア / ごみ箱を見る / ごみ箱のクリア。
- 「カンバン内を検索」を選ぶと、**検索ダイアログ**を開く。タイトル・説明を検索し、対象は開いているプロジェクト内。ブラウザーの検索ショートカット `/` もこのダイアログを開く。ヘッダーを検索フォームへ切り替える機能はない。全プロジェクト検索は、サイドメニュー上部のアプリ名の右にある検索アイコンから開く。
- 同期状態アイコンはタイトルの横にあり、押すと今すぐ同期する。

## 4. 認証とゲスト

認証は Supabase Auth を使う。

### 4.1 ログイン方法

| 方法                | 内容                                                                             |
| ------------------- | -------------------------------------------------------------------------------- |
| メール + パスワード | 登録・ログイン。**メール確認は行わない**。メールアドレスはログイン用IDとして扱う |
| ゲストで使用        | Supabase の匿名認証。登録なしで使い始められる                                    |

入力ルール: メールは形式チェック（小文字化・前後空白除去）。パスワードは8〜72文字・英字と数字を含む。表示名は50文字以内。エラーは種別ごとの文言に変換して表示する。

### 4.2 オフラインでも再ログイン不要にする仕組み

1. ログイン/ゲスト開始に成功したら、「誰として使っているか」（ユーザーID・メール・表示名・ゲストか）を端末に保存する。Supabase のセッションは端末の安全な領域（ネイティブ: Keychain/Keystore、Web: localStorage）に保存する。
2. 起動時は、保存した情報だけで判断してメイン画面を開く。通信やトークン更新の完了は待たない。
3. 通信が必要なのは、**初回のログイン（ゲスト開始を含む）だけ**。以降はオフラインで使える。
4. オンラインに戻ったら、同期が有効なとき自動でトークンが更新される。
5. ログインが無効になった場合（失効など）だけ、データを残したまま画面上部に再ログインの帯を出す。パスワードを入れれば同期が再開する。

### 4.3 ゲスト

- ゲストは Supabase の匿名ユーザー。**ユーザーIDを持つ**ので、同期がオンならデータはサーバーに保存され、RLSでユーザーごとに保護される。
- 同期がオフ、またはオフライン中は、端末内のSQLiteだけに保存する。オンライン復帰後（同期オン）に同期される。
- Supabase が未設定の環境では、ゲストは端末内だけで動く（同期なし）。

### 4.4 ゲストからアカウントへの切り替え

設定 > プロフィール編集 > 「アカウントを作成」で、メール・パスワード・表示名を入力する。

1. 既存の匿名ユーザーにメールアドレスを紐付ける（`updateUser({ email })`）。
2. メールが反映されたことを確認してから、パスワードを設定する（`updateUser({ password })`）。
3. **ユーザーIDは変わらない**ので、端末内・サーバー上のデータはそのまま引き継がれる。以降はアカウントと同じ動作。

メール確認が必要な設定のままだと手順1で反映されず、「メール確認なしでは切り替えられない」旨を表示して中断する。確認方法は `docs/BACKEND.md`。

### 4.5 ゲストからログイン画面へ戻る

設定 > プロフィール編集 > 「ログイン画面に戻る」。警告ダイアログで、ゲストのデータが端末とサーバーから削除され元に戻せないことを示す。実行すると、サーバー側のデータ（オンライン時）と端末内データを削除してログイン画面へ戻る。

### 4.6 ログアウト・パスワード変更・アカウント削除

- ログアウト: 確認ダイアログ（未送信の変更があれば件数を表示）。端末内データを削除する（サーバーのデータは残る）。
- パスワード変更: ログイン後に設定から。現在のパスワードを確認してから新しいパスワードを設定する（要オンライン）。
- アカウント削除: 影響を説明し、「削除」の文字入力と確認ダイアログを経て、Edge Function（`delete-account`）がユーザーとデータを削除する（要オンライン）。

## 5. データモデル

3階層: **プロジェクト → カンバン → タスク**。SQLite と Supabase（PostgreSQL）で同じ構造。IDは端末で生成する UUID。日時は epoch ミリ秒。

### 共通の列

| 列                      | 内容                                                                    |
| ----------------------- | ----------------------------------------------------------------------- |
| id / owner_id           | 主キー / 所有者（Supabase のユーザーID。ゲストは匿名ユーザーのID）      |
| created_at / updated_at | 作成日時 / 最終更新日時（編集した端末の時刻。サーバー時刻との差を補正） |
| deleted_at              | ごみ箱に入れた日時（null なら有効）                                     |
| field_updated_at        | 項目ごとの最終更新時刻（JSON）。競合のマージに使う                      |
| server_seq              | サーバーのみ。書き込みのたびに増える番号（差分取得の基準）              |
| dirty                   | 端末のみ。未送信の変更があるか                                          |

### projects

title(1〜100) / color / is_favorite / sort_key / archived_at（description 列はあるが画面では使わない）

### kanban_columns

project_id / title(1〜50) / color / sort_key / sort_mode(`updated`・`created`・`due`・`color`・`manual`) / is_done_column

### tasks

project_id / column_id / title(1〜300) / description(〜5000) / color / due_at / due_has_time / is_favorite / sort_key / completed_at / archived_at

### 削除・アーカイブ・クリア

- **削除** = ごみ箱へ移動（`deleted_at`）。端末間で削除を伝え、復元できるようにする。
- **アーカイブ** = タスクを非表示にして保管（`archived_at`）。「DONEタスクをアーカイブする」は、DONEモード（`is_done_column`）のカンバンのタスクをまとめてアーカイブする。復元できる。
- **アーカイブのクリア** = アーカイブ済みタスクを完全削除せず、ごみ箱へ移動する。ごみ箱から復元できる。
- **ごみ箱のクリア** = ごみ箱内の項目を完全に削除する（元に戻せない）。
  - ボードの3点メニューからは現在のプロジェクト分、設定からは全プロジェクト分を対象にする。
  - ごみ箱を完全削除する場合、同期が有効なら競合を避けるため先に同期してからサーバー側を削除し、続けて端末側を削除する。同期できない（オフライン）ときは完全削除しない。
  - アーカイブからごみ箱への移動は通常のデータ更新として同期され、他の端末にも反映される。ごみ箱内の項目を完全削除した場合、他の端末に残る同じ項目も次回同期で削除される。
- ごみ箱の自動削除: 既定で30日経過分を削除。設定でON/OFF・日数を変更できる。
- カンバンを削除すると中のタスクも一緒にごみ箱へ（削除前に「別のカンバンへ移動」を選べる）。プロジェクトも同様。親を復元すると、同時に削除された子も戻る。
- 並び順はフラクショナルインデックス（文字列）で管理し、途中への挿入で他の行を更新しない。

## 6. 機能

### 3階層の機能対応

| 機能       | プロジェクト                                             | カンバン                                  | タスク                                   |
| ---------- | -------------------------------------------------------- | ----------------------------------------- | ---------------------------------------- |
| 作成       | メニュー（プロジェクト一覧の直下）「プロジェクトを追加」 | ボード右の横3点メニュー「カンバンを追加」 | カンバン最下部「タスクを追加」           |
| 編集       | 横3点メニュー → 編集                                     | 横3点メニュー → カンバンの編集            | タップ → メニュー → 編集（タスクの編集） |
| 削除       | 横3点メニュー → 削除                                     | 横3点メニュー → 削除                      | タップ → メニュー → 削除                 |
| ピン留め   | あり（一覧の上、横線で区切る）                           | なし                                      | あり（カンバン内の上、横線で区切る）     |
| 並び替え   | —                                                        | 長押しドラッグ / メニューで左右移動       | 長押しドラッグ / 右へ移動ボタン          |
| 複製       | あり（配下も）                                           | あり（タスクも）                          | あり                                     |
| アーカイブ | あり                                                     | なし                                      | あり                                     |
| 色         | あり                                                     | あり                                      | あり（タイトルの左に丸）                 |

### プロジェクト

- 作成・編集はタイトルと色のみ（説明欄はない）。
- 作成時に **TODO（青）・DOING（オレンジ）・DONE（緑）** の3つのカンバンを自動作成（タスクは空。DONEはDONEモード）。
- 横3点メニュー: 編集、ピン留め、複製、アーカイブ、削除。最後に開いたプロジェクトを記憶する。

### カンバン

- 既定は3つ、右上の横3点メニューから追加（上限20）。
- ヘッダー: 色の丸・タイトル・「( 3 )」のような件数・DONEモードのアイコン・横3点メニュー。
- 横3点メニュー: カンバンの編集（名前・色）、タスクの追加、左右へ移動、並び順の切替、**DONEモードの設定/解除**、複製、削除。
- **DONEモード**: ONにしたカンバンのタスクには、タイトル・説明に横線が入る（チェックや「完了」の文字は出さない）。ONにした時点で、すでにあるタスクにも反映される。ヘッダーに目立つアイコン（チェックの二重丸）が出る。「DONEタスクをアーカイブする」の対象になる。

### タスク

- **カード**: タイトルの左に色の丸、タイトル、その下に説明（薄い文字、最大2行。コンパクト表示では非表示）、期限。余白を広くとった大きめのカード。
- **右へ移動ボタン**: カード右端の大きなボタン。次（右）のカンバンへ移動する。いちばん右のカンバンでは**Uターンのアイコン**に変わり、最初のカンバンへ戻す。左へ移動のボタンはない。カンバンが1つだけのときは表示しない。
- **タップ**: カードの下にメニューが開く（編集 / ピン留めにする・解除 / 複製 / アーカイブ / 削除）。カード左側の色の丸を押すと、タスクのタイトルをクリップボードへコピーする（色の変更は編集から行う）。
- **確定ボタン**は青（強調色）。
- **作成・編集ダイアログ**: 最初に見えるのは「タスク名」と「色」。その下の「オプション」（開閉アイコン付き）を開くと、説明、期限、場所（プロジェクト内のカンバンを選択。チェックの位置をそろえて表示）が出る。作成日・更新日は編集時のみ、確定ボタンの上に横に並べて中央寄せで表示（間に余白）。確定ボタンは一番下。複製・アーカイブ・削除・ピン留めは編集画面ではなくタップのメニューから行う。タスク詳細から編集へ移る場合は、詳細ダイアログをアニメーションなしで閉じ、編集ダイアログを待ち時間なしで表示する。固定時間のタイマーや詳細ダイアログの終了待ちは使わず、詳細ダイアログを先に処理する順序でモーダルの競合を抑える。
- **入力上限**: タスク名は300文字、タスク説明は5,000文字まで。複製後のタイトルが上限を超える場合は複製せず、理由をダイアログで表示する。Trello JSON のインポートもプロジェクト名・カンバン名・タスク名・タスク説明の上限を事前検証し、上限超過があればファイル全体を取り込まず、理由をダイアログで表示する。
- **期限**: 年月日のみ（時刻なし）。入力欄の横のカレンダーアイコンから、カレンダーのダイアログで選べる（今日・クリアのボタン付き）。`20261231`（YYYYMMDD、ハイフンなし）の形式で直接入力もできる。入力があるときは、欄の右に×が出て、押すとクリアできる。
- 未保存の変更があるまま閉じると破棄の確認を出す。
- 一覧の並び: 既定は**更新日の新しい順**。**ピン留めは上にまとめ、横線で区切って**その下に通常のタスク（ピンのアイコン（Material Symbols の keep / keep_off）で表す。星は使わない）。カンバンごとに「手動」「更新日」「作成日」「期限」「色」の順序へ切り替え可能。ピン留めしたタスクは選択した並び順にかかわらず上部に表示する。
- **ピン留めの切り替え**: タスクをタップして出るメニューの「ピン留めする / ピン解除」で行う。ドラッグでカンバンを移動しても、ピン留めの状態は変わらない（ピン留めされたタスクは移動先でもピン留めの領域に、されていないタスクは通常の領域に入る）。ドラッグ中に、ピン留め用の置き場は表示しない。
- **ドラッグの見た目**: つかんだ位置が指の真下になる（カードの左上から見た指の位置を保つ）。
- カンバンの最下部、またはカンバンのメニューの「タスクの追加」で、**タスクの編集と同じダイアログ**が開く（タイトルにフォーカスが当たる）。タスクが増えても入力が隠れない。タスクが増えたらカンバン内を縦スクロール。
- 検索結果・移動は更新日が変わるため、操作したタスクは上に来る。

### フォーカスの扱い

新規作成の入力欄は、開いたらすぐ入力できるようフォーカスする。ほかの操作（横スクロール、メニューを開く、ドラッグ、移動ボタンなど）を始めたら、入力欄のフォーカスを外す。

### 初回起動のサンプル（TUTORIAL）

新しく使い始めたとき（ゲスト開始、アカウント登録）に、**TUTORIAL**（色は赤）プロジェクトを1つ作る。カンバンはTODO（青）・DOING（オレンジ）・DONE（緑）。既存アカウントでのログインでは作らない。

| カンバン           | 内容                                                                                                                                                                                                                                                           |
| ------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| TODO               | 機能一覧（右へ移動、長押しドラッグ、ピン留め、編集、カンバン追加・並び替え、検索、同期とオフライン、アーカイブ・ごみ箱、キーボード操作、ゲストからアカウント、タスク追加・複製・並び順、プロジェクト管理、表示設定、インポート・エクスポート、アカウント情報） |
| DOING              | チュートリアルをやってみる                                                                                                                                                                                                                                     |

### 共通

削除・移動・アーカイブの直後に「元に戻す」付きの通知を表示。空状態には案内と作成ボタンを表示。

## 8. 同期

### 8.1 モード（システム設定、端末ごと）

| モード | 動作                                                                                                               |
| ------ | ------------------------------------------------------------------------------------------------------------------ |
| オフ   | 通常は同期しない。既存アカウントへの明示的なログイン時だけ一度同期し、以降は同期しない。アプリ再起動時も同期しない |
| 手動   | 画面を下に引いたとき、同期ボタンのときだけ同期                                                                     |
| 自動   | 変更の数秒後、定期的、ネット復帰時、アプリ復帰時に同期。Webはさらにリアルタイムで変更を受信                        |

既定は Web=自動、スマホ=手動。端末ごとの設定なので、両方自動も両方手動もあり得る。ゲストも同じ設定に従う。

### 8.2 手順

1. **Push**: `dirty` の行を親→子の順に送る。サーバーに同じ行があれば先にマージしてから upsert する。
2. **Pull**: `server_seq` が前回のカーソルより大きい行を500件ずつ取得し、マージして端末に反映する。
3. 後片付け: ごみ箱の自動削除、他端末でクリアされた項目の削除。
4. 送信は `id` 基準の upsert なので、途中で失敗して再実行しても二重適用にならない。

### 8.3 競合解決（項目単位の最終更新優先）

| 状況                   | 結果                                                                                                            |
| ---------------------- | --------------------------------------------------------------------------------------------------------------- |
| 別々の項目を編集       | 両方残る                                                                                                        |
| 同じ項目を編集         | `field_updated_at` が新しい方。同時刻なら値の文字列比較で決める（どの端末でも同じ結果）                         |
| 片方が削除、片方が編集 | 削除（`deleted_at`）も項目の1つとして扱うので、別項目の編集は残り、削除が有効になる。復元は新しい更新として勝つ |
| 時計のずれ             | 同期のたびにサーバー時刻との差を測って補正                                                                      |

マージは `src/domain/merge.ts` の純粋関数。

### 8.4 状態表示

ヘッダー/メニューに「同期済み（時刻）」「同期中」「未送信N件」「オフライン」「エラー」「同期オフ」を表示。自動同期の失敗は指数バックオフ（5秒〜5分）で再試行する。

### 8.5 データの分離

SQLiteは `patto_<ユーザーID>` ごとに分ける。ログアウトすると、そのユーザーの端末内データを削除する。

### 8.6 ブラウザーの複数タブ

Web 版は同じブラウザー内の複数タブから同じユーザーのデータベースを開ける構成だが、タブ間で Zustand の画面状態を共有する仕組みはない。`navigator.locks` が使えるブラウザーでは、データベースの初回オープンとマイグレーションだけを直列化している。各タブの同時編集・画面更新は保証していないため、現状では同じユーザーのデータを複数タブで同時編集しないこと。複数タブを正式にサポートするには、タブ間通知・再読込・書き込み競合の方針を別途実装・検証する必要がある。

## 9. 設定画面

### プロフィール編集

- ゲスト: 「アカウントを作成」（4.4）、「ログイン画面に戻る」（4.5）。
- アカウント: メールアドレス表示、表示名の編集、パスワード変更、ログアウト、アカウント削除（4.6）。

### システム設定

各項目の上に説明文を表示する。ボタン自体は操作名を中心にシンプルにする。

| 分類       | 項目                                                                                                                                                                                      |
| ---------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 外観       | テーマ（システム／ライト／ダーク）、画面の線の太さ（1／2／3）と色、文字サイズ（極小／小／標準／大／特大）、カード密度（コンパクト／標準／詳細）、タスクカードの説明・期限・更新日時の表示 |
| 通知       | トーストのON／OFF。ONの場合は表示時間（1／2／3秒、既定2秒）と、「移動」「作成・複製」「更新・削除など」の3分類ごとの表示対象を設定                                                        |
| 同期       | 同期モード（オフ／手動／自動）、今すぐ同期、最終同期時刻。各モードの説明を表示                                                                                                            |
| データ管理 | Trello形式のJSONインポート／エクスポート。エクスポート前に確認ダイアログを表示                                                                                                            |
| ごみ箱     | 自動削除のON／OFFと保存期間の表示（既定30日）、すべてのごみ箱をクリア、すべてのアーカイブをクリア                                                                                         |
| 初期化     | 端末内データを初期化。実行前に確認ダイアログを表示                                                                                                                                        |

トーストはシステム設定で有効な場合に限り、選択された分類について表示する。

- **移動**: ドラッグや操作によるタスクのカンバン移動、編集ダイアログでのカンバン変更。移動後に「元に戻す」通知を表示する。
- **作成・複製**: タスク・カンバン・プロジェクトの作成、およびそれらの複製。
- **更新・削除など**: 名前などの更新、ピン留めの切り替え、削除・アーカイブの「元に戻す」通知、アーカイブ／ごみ箱のクリア、インポート／エクスポート、初期化、アカウント削除、操作案内など。

トースト表示がOFFの場合は、これらのトーストを表示しない。クリアや初期化の失敗はトーストではなくダイアログで知らせる。

### ショートカット設定画面（Web）

- この画面を開いている間は、キーボードショートカットは反応しない。
- 各操作の行に、割り当てたキーが四角で並ぶ。四角を押すとそのキーを削除できる。キーがなくなっても**点線の空の四角**が残り、点線の四角か「＋」アイコンを押すとキーを追加できる。
- 別の操作で使われているキーを追加しようとした場合の警告は、**そのキーを設定した行**に表示する。
- 「Esc は常にキャンセルに使われます」の右に情報アイコンがあり、押すと設定方法の説明（追加・削除・初期化・複数割り当てなど）をダイアログで表示する。

### よくある質問

- 設定一覧の「よくある質問」から開く。質問と回答をアコーディオンで表示し、同時に開ける回答は1項目だけ。
- 質問・回答本文は `src/config/qa.ts` に定義し、画面コンポーネントへ直書きしない。質問は `Q1.` のような連番と太字、回答は `A.` を付けて通常の太さで表示する。

### アプリについて・ライセンス

- アプリ名・バージョン・著作権表示に続けて、アプリの説明を複数の段落で詳しく表示する（オフライン優先、同期、ゲスト、ピン留め・期限・色・DONEモード・アーカイブ・ごみ箱・検索、キーボード操作、Trello形式の入出力）。
- **使用技術**として Expo / Supabase / Cloudflare のリンクと一言の説明を表示する。Supabase のリンクはダッシュボード（無料プランが7日間の低稼働で停止したとき、ここから再開する）。
- ライセンス（MIT）全文と、利用規約などのリンク（設定されているもののみ）。リンクは `src/config/app.info.json`。

## 10. インポート/エクスポート（Trello形式）

アプリ移行用。1つのプロジェクトを1つの Trello ボード JSON に変換する（複数のときは配列）。

| Patto        | Trello                                                |
| ------------ | ----------------------------------------------------- |
| プロジェクト | ボード（`name` `desc` `closed`）                      |
| カンバン     | リスト（`lists`、並びは `pos`）                       |
| タスク       | カード（`name` `desc` `idList` `due` `closed` `pos`） |
| 色           | ラベルの色（色名はTrelloと同じ）                      |
| DONEモード   | `dueComplete`                                         |
| ピン留め     | `pattoFavorite`（独自項目）                           |

インポートは Trello の書き出しJSONを読み込み、プロジェクトとして追加する（`DONE`/`完了` などの名前のリストはDONEモードにする）。形式が違うファイルはエラー表示。Webはダウンロード、スマホは共有シートで書き出す。

## 11. 共通のUI

### テーマ（白黒ベース）

|                                                                | ライト                                  | ダーク           |
| -------------------------------------------------------------- | --------------------------------------- | ---------------- |
| 背景（画面・ヘッダー・メニュー・カンバン・カード・ダイアログ） | 白（すべて同色）                        | 黒（すべて同色） |
| 境界                                                           | `border` の細い線（カンバンの枠も同じ） | 同左             |
| 文字                                                           | 黒                                      | 白               |

- 背景はすべて同色で、境界は線で区切る。パレットには `bg` `surface` `column` を別項目として残してあり、将来グレーなどに変えるときは `src/theme/palette.ts` の値だけを変える。区切り線（ピン留めの横線、メニューの線など）は専用の `divider`（いまは `border` と同じ値）、ホバー・選択中の背景は `hover`。
- 色を入れたもの（色の丸、赤・黄・青などの状態色）が目立つよう、ベースは白黒。状態色（危険・警告・成功・リンク）とタスクの色は、ライトでは濃く、ダークでは明るくして、どちらの背景でも読めるようにする。
- 「元に戻す」の通知は、画面と反転した面（ライト=黒、ダーク=白）に、その上で読める色の文字を使う。
- 通常の画面枠線・区切り線の基準値は `BORDER_WIDTH = 1`。システム設定で太さを1/2/3、色をタスク色パレットまたはテーマ標準色に変更できる。テーマ標準色はライトが `#D4D4D4`、ダークが `#3A3A3A`。フォーム・ボタンなどのコントロールは独立した `CONTROL_BORDER_WIDTH = 2` を使い、ユーザー設定では変更しない。フォーカス・選択・ドラッグ中などの強調線は `BORDER_WIDTH_EMPHASIS` を使う（`src/theme/tokens.ts`）。
- Webのスクロールバー、ブラウザ標準部品の配色、スマホのステータスバー・ナビゲーションバーの文字/ボタンも、テーマに合わせる。

### 形

- **角丸なし（すべて直角）**: カード、入力欄、ボタン、ダイアログ、メニュー。例外は色を表す丸（色の選択、タイトルの横の色、カンバンの色）のみ。
- 検索欄・タスク追加欄は、囲み線のない（下線だけの）入力欄。

### ロゴ・アイコン

Google の Material Symbols「view_kanban」（Outlined）を、**白背景に黒**で使う。アプリアイコン、ファビコン、スプラッシュ、アプリ内のロゴはすべて同じ。元データは `src/config/logo.ts` と `assets/logo.svg`。

### その他

- ダイアログ: PCは中央のカード、スマホは下から出るシート。PCでは検索・詳細・作成・編集などの最大幅を共通設定により統一する。スマホでキーボードが表示された場合は、ダイアログの下端をキーボードの上端に合わせ、間に余白を設けない。
- 色・余白は `src/theme/`、文言は `src/i18n/ja.ts`、数値は `src/config/` に集約。
- 文字サイズは設定の倍率をすべての文字・アイコンに反映。
- 画面を回転しても入力中の内容を失わない。

## 13. 環境変数とGit管理

### 環境変数

`.env.local` に Supabase の URL と Publishable Key を設定する。`.env.example` が見本（サンプル値入り、Git管理する）。

| 変数                                   | 内容                                   |
| -------------------------------------- | -------------------------------------- |
| `EXPO_PUBLIC_SUPABASE_URL`             | Supabase の Project URL                |
| `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` | Publishable Key（公開前提。RLSで保護） |

Secret Key / service_role キーはアプリに含めない（Edge Function の中だけで使う）。

### Git管理しないもの（`.gitignore`）

`.env` `.env.local` `.env.*.local`、`node_modules/`、`.expo/`、`dist/`、`android/` `ios/`、`supabase/.env` `supabase/.temp/`、署名鍵（`*.keystore` `*.jks` `*.p8` `*.p12` `*.key` `*.mobileprovision`）。
Git管理するもの: `.env.example`、`pnpm-lock.yaml`、`supabase/migrations/`、`supabase/functions/`、`public/_headers`。
